Домашнее задание

Создайте несколько MCP-инструментов, например: search, summarize, saveToFile.

  • Реализуйте пайплайн: первый инструмент получает данные.
  • Второй — обрабатывает.
  • Третий — сохраняет результат.
  • Проверьте автоматическое выполнение цепочки.
  • Проверьте корректность передачи данных между инструментами.

Практика

Одна просьба — несколько вызовов подряд

В дне 17 на один вопрос обычно хватало одного инструмента. Теперь задача такая, что одним не обойтись: сначала достать данные, потом их обработать, потом сохранить. Порядок вызовов в коде не прописан — модель сама видит результат первого инструмента и из него формулирует вызов второго.

В 19 дне задача была сделать цепочку из tools scheme.

Не обязательно, это пример. Можно любую цепочку тулов.

Алексей Гладков, 25.09 — что цепочка живёт внутри одного MCP-сервера и что search → summarize → save лишь пример
  1. 01

    Один сервер — много тулов

    Цепочка собирается из инструментов одного MCP-сервера: одна схема, внутри несколько тулов, каждый делает свою часть. Несколько серверов — это уже день 20.

    search · summarize · save

  2. 02

    Цепочку строит агент

    Нет кода «вызови A, потом B». Модель получает результат A и по нему сама формулирует вызов B — Гладков на вопрос, так ли это, ответил «Ага».

    A → результат → вызов B

  3. 03

    Передача данных

    Выход одного инструмента становится входом следующего. Проверяем именно это: что дошло до второго и третьего шага без потерь и без выдумки.

    выход A = вход B

  4. 04

    Итог на диске

    Последний инструмент сохраняет результат в файл. Файл можно открыть и сверить с тем, что вернули первые два шага.

    → save → файл
