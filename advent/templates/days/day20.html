Практика

Один агент — несколько серверов

До сих пор агент говорил с одним MCP-сервером за раз. Теперь за ним стоят сразу несколько: у каждого свой транспорт и свой набор инструментов. Агент сам решает, какой инструмент нужен, отправляет вызов на тот сервер, где он живёт, и ведёт задачу дальше — результат одного сервера становится запросом к другому.

А в 20 дне — из нескольких MCP и нескольких tool scheme.

Если у тебя за время работы 2–3 таких вот MCP с кучей тулов, это будет тянуться и тянуться.

Алексей Гладков, 23–25.09 — чем день 20 отличается от 19 и чем платят за несколько серверов
  1. 01

    Реестр серверов

    Несколько MCP-серверов за одним агентом: чужой в интернете и свои, по HTTP и по stdio. У каждого своя tool scheme — агент видит их все сразу.

    GitMCP · GitHub · курс

  2. 02

    Маршрутизация

    Модель называет только инструмент. На какой сервер отправить вызов, решает агент — по реестру «инструмент → сервер». Совпали имена у двух серверов — это надо развести заранее.

    имя тула → сервер

  3. 03

    Длинный флоу

    Задача, которую один сервер не закрывает: что-то нашли на одном, по найденному спросили другой, итог сохранили третьим. Данные переходят между серверами.

    сервер A → сервер B → итог

  4. 04

    Выбор и цена

    Проверяем, что каждый вызов ушёл на правильный сервер и в правильном порядке. И считаем цену: схемы всех серверов едут в каждый запрос к модели.
