День 15.
Контролируемые переходы

Домашнее задание

Реализуйте явные переходы между состояниями задачи.

  • У задачи есть допустимые состояния.
  • Между ними есть разрешённые переходы.
  • Ассистент не может «перепрыгнуть» этап.
  • Пример: нельзя делать реализацию до утверждённого плана; нельзя делать финал без валидации.
  • Проверьте попытки перейти в недопустимое состояние и реакцию ассистента.
  • Проверьте корректность продолжения после паузы.

Практика

Переход — это разрешение, а не желание

В дне 13 автомат уже двигал задачу по этапам, но переходы были зашиты в методы и стояли на честном слове: «утвердить» можно было нажать сразу, а модель могла сказать «готово» без проверки. Теперь правила переходов — отдельная таблица: откуда, куда, при каком условии. Всё, чего в таблице нет, — недопустимо, и на такую попытку ассистент отвечает отказом с объяснением, а не тихо перепрыгивает.

  1. 01

    Таблица переходов

    planning → execution только по утверждению плана; execution → validation только когда все шаги закрыты; validation → done только по вердикту «принято»; validation → execution — возврат на шаг.

    откуда · куда · условие

  2. 02

    Guard'ы

    Условие перехода — функция над состоянием: план не пуст, шаги закрыты, вердикт стоит. Не выполнилось — перехода нет, даже если нажали кнопку или модель сказала «готово».

    guard(state) → да / нет + причина

  3. 03

    Прыжок запрещён

    Попытка «сразу к финалу» или «давай код без плана» — недопустимый переход. Ассистент отказывает, называет текущий этап и что нужно, чтобы двинуться дальше.

    перехода нет в таблице → отказ + путь

  4. 04

    Пауза — не состояние

    Пауза не меняет этап, а замораживает его: после неё можно только продолжить с того же места. Продолжение проверяется так же, как в дне 13 — без пересказа.

    pause ⟲ resume, этап тот же
