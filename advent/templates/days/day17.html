Домашнее задание

Реализуйте свой MCP-сервер вокруг любого API (например: Яндекс.Трекер, Git, CRM, mock API).

  • Сделайте регистрацию инструмента.
  • Сделайте описание входных параметров.
  • Сделайте возврат результата.
  • Подключите инструмент к своему агенту и вызовите его из приложения.
  • Получите и используйте результат.
Ожидаемый результат
Агент делает вызов к MCP-инструменту и получает результат.
Формат
Видео + код

Практика

Модель просит — агент вызывает

В дне 16 мы только спросили чужой сервер, что он умеет. Теперь сервер свой, а инструмент реально вызывается. Но вызывает его не кнопка и не модель: модель видит схему и просит вызов, агент ходит в MCP и возвращает ей результат, а модель уже отвечает пользователю.

Ага, дёргаешь агента — он дёргает какие нужно MCP-вызовы.

Алексей Гладков, 24.09 19:37 — на вопрос, должен ли агент сам понять, какой инструмент использовать
  1. 01

    Свой сервер

    Та же библиотека mcp, что в дне 16, только серверная половина — MCPServer. Внутри — обёртка вокруг API, снаружи — обычный MCP.

    API → MCPServer → stdio

  2. 02

    Регистрация

    Функция на Python с декоратором @server.tool(). Имя, описание и схема параметров берутся из сигнатуры и docstring — руками JSON Schema не пишем.

    def + аннотации → inputSchema

  3. 03

    Цикл вызова

    Схемы уходят модели в поле tools. Модель отвечает не текстом, а просьбой вызвать инструмент. Агент вызывает его через MCP и кладёт результат обратно в диалог.

    tools → tool_call → call_tool → result

  4. 04

    Результат в деле

    Результат — не финал, а сырьё: модель читает его и строит ответ пользователю. На странице видно, что попросила модель, что вернул сервер и что из этого вышло.

    result → ответ модели
