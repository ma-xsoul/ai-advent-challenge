Индексация документов

Домашнее задание

Возьмите набор документов: README / статьи / код / pdf → текст, минимум 20–30 страниц текста суммарно (или эквивалент в коде).

  • Реализуйте пайплайн индексации: разбиение на чанки (chunking).
  • Генерация эмбеддингов.
  • Сохранение индекса (FAISS / SQLite / JSON).
  • Усиление: добавьте метаданные к каждому чанку (source, title/file, section, chunk_id).
  • Усиление: сделайте минимум 2 стратегии chunking и сравните их — по фиксированному размеру и по структуре (заголовки/разделы/файлы).
Ожидаемый результат
Локальный индекс документов с эмбеддингами + метаданные + сравнение 2 стратегий chunking.
Формат
Видео + код

Практика

Сначала база, потом ответы по ней

Неделя RAG: модель будет отвечать не по памяти, а по нашим документам. Первый шаг — превратить документы в индекс: нарезать на куски, каждому куску дать вектор-«отпечаток» смысла и сложить всё так, чтобы по вопросу быстро находились нужные куски. Сегодня отвечать ещё ничего не нужно — только построить базу и проверить, что поиск по ней что-то находит.

Пока просто нужно сделать разбиение на чанки.

Это типа задача со звёздочкой… Просто разделил на две части, чтобы проще было понять, что база, что усиление.

Алексей Гладков, 28–29.09 — что требуется в день 21 и что значит блок «Усиление»
  1. 01

    Корпус

    Что индексируем: документы и код, переведённые в текст, — не меньше 20–30 страниц. Каждый файл помнит, откуда он, чтобы ответ потом мог на него сослаться.

    файлы → текст

  2. 02

    Чанкинг

    Две стратегии нарезки: кусками фиксированного размера с перекрытием — и по структуре: заголовкам документа, функциям и классам кода. Сравниваем, что выходит лучше.

    размер · структура

  3. 03

    Эмбеддинги

    Каждый чанк превращается в вектор — числовой отпечаток смысла. Похожие по смыслу тексты дают близкие векторы, даже если слова в них разные.

    чанк → вектор

  4. 04

    Индекс

    Векторы и метаданные — source, файл, раздел, chunk_id — ложатся в локальный индекс. Проверка: по запросу индекс отдаёт top-K ближайших чанков.

    вектор + метаданные → top-K
