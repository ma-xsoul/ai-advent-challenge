День 34.
Ассистент для работы с файлами проекта

Домашнее задание

Сделайте ассистента, который активно работает с файлами, а не просто отвечает текстом.

Через MCP или доступный вам tooling ассистент должен уметь:

  • читать файлы проекта
  • искать информацию по нескольким файлам
  • анализировать содержимое
  • создавать или изменять файлы

Примеры сценариев (реализуйте минимум 2):

  • найти все места, где используется определённый компонент / API
  • обновить документацию на основе изменений в коде
  • сгенерировать новый файл (README / ADR / changelog)
  • проверить соответствие файлов правилам или инвариантам
  • подготовить diff или список изменений

Важно:

  • ассистент сам инициирует работу с файлами
  • вы задаёте задачу на уровне цели, а не “открой файл X”

Минимальный результат:

  • ассистент работает минимум с 2–3 файлами
  • изменения сохраняются или выводятся как diff
  • результат можно воспроизвести повторно
Ожидаемый результат
AI-ассистент, который выполняет реальные операции с файлами проекта.
Формат
Видео + код

Практика

Не отвечает, а делает

До сих пор ассистенты отвечали текстом. Сегодняшний сам работает с файлами проекта: вы ставите цель — «найди, где используется ndjson_stream», «проверь, что у каждого дня есть всё нужное», «обнови документацию под новый код», — а он сам ищет по файлам, открывает нужные, разбирается и готовит изменения. Вслепую ничего не пишется: страница показывает diff, применяете кнопкой.

Вообще вся эта неделя нужна для того, чтобы пособирать разные решения. Эта неделя она более продуктовая.

Ну типа подумайте, куда это можно применить. Вот эти ваши знания. Пособирайте пайпы.

Алексей Гладков, 14.10 — зачем нужна последняя неделя челленджа
  1. 01

    Инструменты для файлов

    Свой MCP-сервер над файлами проекта: список, поиск по нескольким файлам, чтение кусками, запись. Какие файлы открыть — решает ассистент.

    list · search · read · write

  2. 02

    Задача на уровне цели

    Вы пишете, что нужно получить, а не какой файл открыть. Ассистент сам строит план: где искать, что прочитать, что сравнить.

    цель → поиск → файлы

  3. 03

    Изменения как diff

    Правки сначала копятся как черновик и показываются diff'ом. Применить или выбросить — решает человек. Ту же задачу можно запустить снова и сравнить.

    черновик → diff → применить

  4. 04

    Сценарии

    Найти все использования API, проверить файлы на правила проекта, обновить документацию или собрать changelog — по одной кнопке на сценарий.

    найти · проверить · сгенерировать
