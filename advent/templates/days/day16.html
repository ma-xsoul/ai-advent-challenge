Подключение MCP

Домашнее задание

Установите MCP SDK / клиент (или поднимите MCP-сервер, если используете локальный вариант).

  • Сделайте минимальный код, который устанавливает MCP-соединение.
  • Получите от MCP список доступных инструментов.
  • Проверьте, что соединение устанавливается.
  • Проверьте, что список инструментов корректно возвращается.
Ожидаемый результат
Код, который подключается к MCP и выводит список доступных инструментов.
Формат
Видео + код

Практика

Соединение встало — что на той стороне

Первые пятнадцать дней агент жил на одном слое промпта: всё, что он знал и умел, приходило текстом. MCP добавляет второй канал — инструменты. Сегодня без вызовов: встать в соединение и честно показать, что сервер предлагает — имена, описания и схемы входа. Клиент — официальный MCP SDK для Python; справа на странице каждое сообщение, которое он отправил и получил.

Здесь пока с MCP работать не нужно — просто запросить геттулз у любого общедоступного mcp.

Алексей Гладков, 21.09 14:03
  1. 01

    Транспорт

    Клиент сам запускает сервер процессом и говорит с ним по stdio — либо ходит по HTTP к уже поднятому. Свой сервер сегодня не нужен: берём общедоступный.

    stdio · процесс · JSON-RPC

  2. 02

    Рукопожатие

    initialize — стороны называют версию протокола и свои возможности. SDK v2 сначала пробует новый server/discover, а на отказ откатывается к классике. Пока рукопожатие не прошло, спрашивать нечего.

    discover? → initialize → initialized

  3. 03

    tools/list

    Единственный запрос дня. Сервер отдаёт список: имя инструмента, описание и схему входа. Вызывать ничего не будем — это день 17.

    запрос · список · без вызова

  4. 04

    Цена схемы

    Схема каждого инструмента уходит в модель и занимает токены в каждом ходу. Счётчики у нас есть с дня 8 — посчитаем, во что обходится сам список.

    схема → токены → каждый ход
