# Архитектура проекта AI Advent

## Что это

Лаборатория домашних заданий челленджа AI Advent: одно Flask-приложение,
в котором каждый день — отдельная страница `/days/<N>/` со своим API.
Дни не заменяют друг друга, а надстраиваются: агент дня 6 живёт и в
днях 7–15, MCP дня 16 — в днях 17–20 и 31, индекс дня 21 — во всей
неделе RAG, в неделе локальных моделей и в ассистенте разработчика.

Каждый день делается в своей git-ветке `day-N`, ветка следующего дня
отходит от предыдущего. `main` не трогается.

## Стек

- Python 3.12, Flask 3.1, шаблоны Jinja, без фронтенд-фреймворков:
  на каждой странице свой маленький скрипт на чистом JS.
- Облачная модель — DeepSeek (`deepseek-v4-flash`) через
  `advent/agent/transport.py`; в дне 5 — OpenRouter.
- Локальные модели — Ollama на `localhost:11434`: `bge-m3` для векторов
  (день 21+), `gpt-oss:20b` и `gemma4:12b` для ответов (дни 26–30).
- MCP — официальный Python SDK `mcp`: клиент, свои серверы, агент.
- Хранилище — файлы: JSON на сессию и SQLite в папке `data/`.

## Слои

| Папка | За что отвечает |
|---|---|
| `advent/__init__.py` | фабрика приложения `create_app`: регистрирует blueprint'ы дней и принимает подмены для тестов |
| `advent/navigation.py` | список дней `DAYS`: номер, название, адрес, статус — из него строится меню |
| `advent/agent/` | агент (день 6+): конфиг, история, токены, стратегии контекста, память, профиль, задача-автомат, инварианты |
| `advent/mcp/` | MCP: клиент и реестр серверов, агент с инструментами, свои серверы в `servers/` |
| `advent/rag/` | RAG (день 21+): корпус, нарезка, эмбеддинги, индекс, ответ, реранк, цитаты, мини-чат |
| `advent/local/` | локальные модели (день 26+): клиент Ollama, транспорт, локальный RAG, оптимизация, приватный сервис |
| `advent/scheduler/` | тик по расписанию для cron (день 18) |
| `advent/services/` | прямые интеграции с DeepSeek и OpenRouter первых дней |
| `advent/days/dayNN/routes.py` | blueprint дня: страница и её API |
| `advent/templates/days/` | шаблон каждого дня; общая оболочка — `templates/base.html` |
| `advent/static/` | общие и дневные стили и скрипты |
| `service.py` | отдельный процесс приватного сервиса дня 30 |
| `tests/` | unittest: страницы, API, модули — с подменами вместо сети |

## Как идёт запрос

1. Страница дня шлёт `fetch` в свой API: `/days/<N>/api/...`.
2. Blueprint берёт зависимости из конфига приложения — транспорт модели,
   клиент Ollama, пути к файлам — или создаёт настоящие.
3. Модуль из `agent/`, `rag/`, `mcp/` или `local/` делает работу и
   ходит к модели через транспорт.
4. Долгие ответы идут потоком NDJSON: по строке JSON на событие с полем
   `type` (`advent/days/rag_pages.py` → `ndjson_stream`). Страница
   рисует события по мере прихода.

## Агент и MCP

`advent/mcp/agent.py` — цикл хода: модель видит схемы инструментов, просит
`tool_calls`, агент вызывает их через MCP (`tools/call`) и возвращает
результат модели, пока она не ответит текстом. Кругов не больше четырёх.
С несколькими серверами имена инструментов получают префикс сервера
(`git__git_branch`), и агент маршрутизирует вызов по префиксу.

Свои MCP-серверы запускаются процессом по stdio
(`python -m advent.mcp.servers.<имя>`):

- `github` — поиск и сравнение репозиториев GitHub, отчёт в файл (дни 17, 19);
- `rates` — курс доллара: снимки в SQLite, сводка, история (день 18);
- `git` — репозиторий самого проекта: ветка, изменения, diff, история,
  список файлов, только чтение (день 31).

## RAG

Корпус (`advent/rag/corpus.py`) — сам проект: README и `docs/*.md`, код
`advent/**/*.py` и тексты страниц дней. Нарезка по структуре режет
markdown по заголовкам, код — по функциям и классам; векторы считает
`bge-m3`. Индекс — один SQLite-файл: куски с метаданными (файл, раздел,
строки), векторы и кэш векторов по хэшу текста, поэтому пересборка
считает заново только изменившиеся куски. Поиск — косинусная близость,
top-K.

Ответ с доказательствами (`advent/rag/grounded.py`): модель сначала
выписывает дословные цитаты из найденных кусков, потом отвечает только по
ним; цитаты проверяются кодом.

## Данные на диске

Папка `data/` не попадает в git — это состояние конкретной машины.

| Путь | Что |
|---|---|
| `data/agents/<сессия>-*.json` | диалоги агентов, память, профили, задачи |
| `data/day18/rates.sqlite3` | снимки курса доллара |
| `data/day19/`, `data/day20/` | отчёты агентов в markdown |
| `data/day21/index.sqlite3` | индекс недели RAG |
| `data/day28/runs.json`, `data/day29/runs.json` | прогоны контрольных вопросов |
| `data/day30/keys.json` | ключи приватного сервиса и ключ администратора |
| `data/day31/index.sqlite3` | свежий индекс ассистента разработчика |

## Тесты

`.venv/bin/python -m unittest -q` — без сети и без моделей: транспорт,
клиент Ollama, эмбеддер и HTTP подменяются через конфиг приложения, файлы
пишутся во временные папки. MCP-серверы в тестах подключаются в памяти
(`InMemoryTransport`), git-сервер — к временному репозиторию.

## Как добавить день

1. Blueprint в `advent/days/dayNN/routes.py` и регистрация в `advent/__init__.py`.
2. Шаблон `advent/templates/days/dayNN.html`, стили и скрипт в `advent/static/`.
3. Строка в `advent/navigation.py` — со статусом «В работе», потом «Готово».
4. Тест страницы в `tests/test_app.py` и строка в README.
